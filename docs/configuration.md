# 密码本配置与密钥

首次克隆在仓库根目录运行：

```bat
python tooling\init_config.py --url http://vault.local:8443
```

每个新副本独立生成随机配置，脚本不显示密钥；已有配置时仅检查并重新生成头文件，不自动更换密钥。部分配置丢失或双端不一致时拒绝继续，需要先恢复配套文件。

| 本地文件 | 用途 |
| --- | --- |
| `firmware/vault-sync-key.properties` | 编入设备的同步认证密钥 |
| `server/vault-sync-key.properties` | 编入 JAR 的同步认证密钥，必须与设备端一致 |
| `server/deployment/local-keys.json` | 稳定的存储密钥、密码本 ID、盐和通信令牌 |
| `firmware/vault-connection.json` | 生成固件默认服务器地址的本地配置 |
| `firmware/main/core/vault_builtin.hpp` | 根据稳定身份生成的固件私有头文件，不手动编辑 |

以上文件均已忽略。不要只把 JAR 交给自己另一台服务器而遗漏配套身份，也不要在每次编译前重新生成存储身份。

通过 Git 提交源码时这些本地文件不会进入提交列表。手工上传或压缩整个目录不会应用 `.gitignore`，公开分发前须排除这些文件；其他使用者通过初始化脚本生成自己的身份。

同步认证密钥是 64 位十六进制值。需要更换时编辑两个 `.properties`，保持一致，再重新编译、部署服务端和烧录设备；它与存储密钥分开，因此单独更换同步认证密钥不会改变已保存密码文件的加密身份。

`local-keys.json` 中的存储身份必须长期保存。更换它会建立不同的部署，不能直接读取旧身份加密的数据。初次克隆生成新身份属于预期行为，不会自动获取原设备或原服务的数据。

`vault.local` 只是示例。实际设备需要连接能访问服务的 Wi-Fi，地址应为可解析主机名或 LAN IP，不能用 `127.0.0.1` 指向电脑。服务器的 `VAULT_PUBLIC_URL` 必须与浏览器访问地址一致。

SD 卡同步后备配置是 `config/vault.json`，模板位于 `resources/sdcard/config/vault.json`。设备优先按当前配置同步，失败后尝试读取卡中地址；只有同步成功才保存新地址。文件格式以 [密码本说明](firmware/password_vault.md) 为准。

设备首次进入密码本设置纯数字管理员密码；服务端首次访问设置至少四位管理员密码。两者分别管理本地解锁，并不要求使用相同管理员密码。同步时以服务端密码数据覆盖设备列表。
